# 文献与专利检索

用于两个场景：建库第 4 步（建对标层），以及日常的「帮我查一下 XX 主题的论文/专利」。

## 先说和 agent-reach 的分工

如果环境里有 `agent-reach` skill，**不要重复造它的能力**：

| 需求 | 用谁 |
|---|---|
| 通用网页搜索、技术博客、社区讨论 | **agent-reach**（Exa / 各平台 CLI） |
| GitHub 仓库与代码 | **agent-reach**（`gh` CLI） |
| 网页正文抓取、RSS | **agent-reach**（Jina Reader） |
| **学术论文检索** | **本文档**（agent-reach 不覆盖） |
| **专利检索** | **本文档**（agent-reach 不覆盖） |

agent-reach 的 search 后端是 Exa + GitHub，面向通用网页和代码，**没有学术库和专利库**。所以这两块由本 skill 自带脚本承担。开工前跑一次 `agent-reach doctor --json` 看它当前哪些后端可用，能用的就用它。

## 网络路由：境外 vs 国内

这是本节最关键的一条。**本 skill 自带脚本调用的全是境外 API，在受限内网中不可用。**

| 环境 | 论文 | 专利 |
|---|---|---|
| 可联网环境（家里 / 个人设备） | `scripts/paper_search.py`（arXiv + Crossref） | `scripts/patent_search.py`（Google Patents） |
| 受限内网（只通国内） | 浏览器访问知网 / 万方 / 百度学术 / ChinaXiv | 浏览器访问国知局检索系统 / 佰腾 |

**推荐做法**：检索在可联网环境做，结果**连同摘要全文一起**冻结进 `_kb/landscape/`，带回内网离线使用。理由是内网里链接点不开，只存链接等于没存。

国内各入口的实测 URL 见知识库里的 `_kb/landscape/国内检索入口.md`（该文件由本流程首次建库时产出）。

## 自带脚本

### 论文检索

```bash
python3 scripts/paper_search.py "four wheel independent steering"
python3 scripts/paper_search.py "4WIS control allocation" --source crossref --limit 12
python3 scripts/paper_search.py --ids 2412.02953,2403.12487    # 按 arXiv ID 补全整摘要
```

后端说明：

- **arxiv** —— 预印本，摘要完整，稳定无 key。缺点是**只有预印本**，正式期刊论文覆盖不到
- **crossref** —— 正式期刊与会议，**覆盖中文期刊**（如《机械工程学报》、中国控制会议），是 arXiv 的关键补充。部分条目无摘要
- **s2**（Semantic Scholar）—— 带引用数，但无 key 时经常 429，仅作可选

**两个后端都要跑。** 只跑 arXiv 会漏掉正式发表文献，只跑 Crossref 会丢摘要。

### 专利检索

```bash
python3 scripts/patent_search.py '"four wheel independent steering"'
python3 scripts/patent_search.py '"四轮独立转向" 容错' --limit 10
python3 scripts/patent_search.py 'assignee:"吉林大学" 转向' --count-only
```

支持 Google Patents 检索语法（引号短语、`assignee:`、`inventor:`、`before:`/`after:`）。**中文检索式同样有效，而且中文专利往往是最相关的现有技术，别只用英文检索。**

`--count-only` 只看命中总量，用途是判断某方向有多挤：命中几千件通常意味着新颖性空间已经很窄，创新点要往更具体的组合上聚焦。

**注意**：Google Patents 对连续请求会 503 限流，脚本内置退避重试；连续跑多个检索式时自行隔几秒，别把重试当常态。

## 怎么设计检索式（这一步决定召回率）

弱模型最典型的失误是**拿用户原话搜一次就完事**。合格的检索至少要做到：

**一、术语扩展。** 同一概念的多种说法都要试：
```
四轮独立转向 / 4WIS / four wheel independent steering / 4WIS-4WID
线控转向 / SBW / steer-by-wire
蟹行 / 斜行 / diagonal / crab / lateral movement
原地转向 / 零半径回转 / zero-turn
```

**二、中英文都要跑。** 中文库和英文库的内容重叠度很低，尤其国内高校成果大量只在中文库。

**三、按申请人/机构检索。** 从初筛结果里找出高频出现的机构（例如某几所高校或某个 Tier1），再对它们做专项检索——同一家的专利往往成族布局，只看到一件容易误判。

**四、顺藤摸瓜。** 找到一篇高相关文献后，看它的参考文献和被引，比继续换关键词更有效。

**五、专门找一篇近年综述。** 综述能一次性给出全局图景和分类框架，比零散地攒二十篇论文效率高得多。写论文的 Related Work 尤其需要。

## 结果怎么落库

脚本输出已经是 `PAPERS.md` / `PRIOR_ART.md` 的条目格式，直接粘贴，然后**必须补两件事**：

**一、「与本项目关联」字段。** 脚本留了 `<待填>` 占位。不填的话，三个月后没人知道当初为什么收录这一条，这条就成了噪音。填一句话说明它对项目哪个具体问题有用。

**二、摘要要留全。** 不要为了美观截断。知识库要在无外网环境使用，摘要就是离线时唯一能读到的内容。

另外记得更新文件末尾的**检索记录表**（检索式、库、命中数、日期）和**已知缺口**——下次续做时，这两项决定了你知不知道上次做到哪、漏了什么。

## 专利检索的额外纪律

**一、脚本产出的是初筛线索，不是检索报告。** 未做同族合并、未做权利要求比对、未做法律状态核验。任何 FTO 判断或申请决策必须由专利代理人或专业检索机构出正式报告。**这句话要主动告诉用户，不要让他误以为跑完脚本就检索完了。**

**二、不要填"风险等级"。** 判断一件专利是否构成障碍需要逐条比对权利要求。**填一个没依据的风险等级，比留空危险得多**——它会被当成结论用。脚本刻意把这一栏留空给代理人。

**三、留意背景技术里的"自认缺陷"。** 现有专利在背景技术中承认的行业痛点，反过来正是你方工作的价值论证依据，写交底书的"要解决的技术问题"时可以引用。这类句子很值钱，检索时留意摘出来。

**四、公开时序。** 若同时在准备论文和专利，提醒用户确认申请与发表的先后——论文公开可能破坏自己专利的新颖性。详见 `deliverables.md` 末节。
