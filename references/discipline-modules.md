# 学科模块清单（机电一体化 / 汽车电子类项目）

## 这份清单解决什么问题

建理论层时最容易犯的错是**只建"项目最显眼的那个学科"**。一个四轮转向项目，很容易只建车辆动力学和转向几何，然后在评审时被问到"你们电机的转矩响应带宽多少""CAN 负载率多少""软件按什么流程验证的"——这些都属于项目实际依赖、但不显眼的学科。

这份清单是个**检查表**：对照过一遍，确认每个模块是"确实用不上所以不建"，而不是"没想到"。

## 重要：这里只有模块定义，没有理论内容

**理论内容写进知识库的 `_kb/theory/`，不写进本 skill。** 两个原因：

1. **溯源标注会丢。** `theory/` 下的内容带 `[已查证]` / `[仅模型知识]` 标记，读者知道哪些能直接引用、哪些必须先查证。写进 skill 就变成了指令口吻，这层信息没了——而弱模型会把指令当权威，直接引进论文和专利。
2. **上下文预算。** SKILL.md 每次触发都全量入上下文。用户只想列个会议提纲时，不该为五个学科的理论付费。

所以本文件只回答"该建哪些模块、每个模块要覆盖什么、常见坑在哪"，具体内容按 `build-playbook.md` 第 3 步的格式落到 `theory/` 里。

## 模块清单

每个模块给出：**覆盖什么** / **能回答什么问题** / **常见欠账** / **权威来源方向**

### M1 · 领域本体学科
> 项目所属的那个专业本身。汽车转向类即转向几何、车辆动力学。

- **覆盖**：该领域的几何/物理模型、关键指标定义、稳态与瞬态特性
- **回答**：为什么这么设计、指标为什么定在这个值、性能瓶颈的机理是什么
- **常见欠账**：只做低速/静态分析，不建动态模型，高速或瞬态问题到样机阶段才暴露
- **来源方向**：本专业教材、行业标准、SAE/ISO 术语定义

### M2 · 控制理论与算法
- **覆盖**：被控对象建模、控制律设计、稳定性分析、参数整定、降级策略
- **回答**：控制策略怎么选、参数怎么调、失稳的机理、算不出来时退到哪
- **常见欠账**：只有主控策略没有降级路径——方案评审必问"降级到哪里"
- **来源方向**：控制理论教材、领域内控制方向的期刊论文

### M3 · 执行机构与驱动（含 FOC 电机控制）
- **覆盖**：电机原理与选型、矢量控制/FOC、Clarke/Park 变换、电流环-速度环-位置环、PWM 与逆变、传感器（编码器/旋变）、热与电流限制
- **回答**：转角精度由什么决定、响应带宽够不够、大负载工况下电流冲击从哪来、堵转怎么保护
- **常见欠账**：把执行机构当黑盒。外购件也要理解其带宽、背隙、温升限制，否则上层控制的假设是空的
- **来源方向**：电机控制教材、芯片厂商应用手册（TI/ST 的 FOC 文档质量很高且公开）

### M4 · 机械设计与结构
- **覆盖**：传动链（减速器类型、速比、背隙、刚度）、强度与疲劳、公差链、材料选择、簧下质量、装配与维修性
- **回答**：精度损失在哪一环、寿命够不够、为什么选这个传动方案、重量代价多大
- **常见欠账**：只算强度不算刚度和背隙——而这两项直接决定控制精度上限
- **来源方向**：机械设计手册、材料与疲劳标准、减速器厂商样本

### M5 · 车载通信（CAN / CAN FD / 车载以太网）
- **覆盖**：CAN 协议基础（仲裁、差分信号、标准帧/扩展帧）、CAN FD、ISO 11898 各部分、报文设计与 DBC、总线负载率、时延与抖动、诊断（UDS）、网络管理
- **回答**：控制指令的端到端时延多少、总线负载够不够、报文丢失时怎么办、诊断怎么做
- **常见欠账**：时延与抖动没纳入控制回路设计——控制器按理想采样周期设计，实际总线抖动使性能打折
- **来源方向**：ISO 11898 系列、Bosch CAN 规范（免费公开）、CiA 规范

### M6 · 嵌入式软件与 MBD
- **覆盖**：V 模型开发流程、MBD 四步（建模-控制器设计-仿真-部署）、自动代码生成、MIL/SIL/HIL、实时性与调度、AUTOSAR（若适用）、版本与配置管理
- **回答**：软件怎么验证的、模型和代码怎么保持一致、实时性怎么保证、改一处怎么知道没破坏别处
- **常见欠账**：仿真做得好但 HIL 缺位；模型与手写代码双轨并存导致不一致
- **来源方向**：MBD 工具链官方文档、AUTOSAR 规范、ISO 26262 软件部分

### M7 · 功能安全与可靠性
- **覆盖**：HARA、ASIL 定级、安全机制、失效模式（FMEA）、冗余架构、故障检测覆盖率、降级策略
- **回答**：这个失效会怎样、检测得出来吗、检测出来之后怎么办
- **常见欠账**：样机阶段整体缺位，而冗余架构会反向约束电气架构和软件架构，后补代价极高
- **来源方向**：ISO 26262 / GB/T 34590 标准原文。**这块必须由有资质的工程师确认，不要采信模型输出**

### M8 · 数学与物理基础
> 横跨上面所有模块的公共语言。

- **覆盖**：坐标系与坐标变换、刚体运动学、拉氏变换与传递函数、状态空间、离散化与采样定理、数值积分、最优化基础、概率与误差分析
- **回答**：各模块之间的符号和坐标约定为什么要统一、离散化误差从哪来、估计精度的理论下界
- **常见欠账**：**坐标系约定不统一**——这是跨团队协作最高频的低级错误来源，值得单独立一节明确写死
- **来源方向**：工科数学、信号与系统、现代控制理论教材

## 理论模块的写法模板

下面这套结构提炼自一部实际写成的工程讲义（9 篇、15 万字、含公式推导与派生的 HTML/Word/PPT 版本），是经过实战检验的组织方式，比凭空设计的模板可靠。**建理论模块时照这个结构写。**

### 全局：先立一条主线

好的理论层不是模块的堆叠，而是**一条贯穿全部模块的因果主线**。那部讲义的主线是一句话：

> 车辆与地面只通过四个橡胶接触印迹交换力，一切性能最终受接触印迹的附着能力约束。

有了主线，每个模块都能回答"我在这条链上的哪个位置"，读者（和弱模型）不会迷失在孤立知识点里。**动笔前先把主线写出来，写不出来说明理论层的组织还没想清楚。**

### 单个模块的结构

```markdown
# 第 N 篇 · <模块名>

> **一句话**：<用一句话说清本模块的核心结论>

<承上启下：上一模块解决了什么，本模块要回答什么问题>

## N.1 <小节>

<正文>

📐 **公式卡**
$$<公式>$$
变量说明：
- $x$：<含义与单位>

⚠️ **边界提醒**
<这条结论在什么条件下成立、什么时候失效>

## ...

## 常见误区
```

四个要件缺一不可：

- **「一句话」导语** —— 强制作者提炼，也让读者（含弱模型）快速判断该不该展开读。检索时命中这一句就够决定要不要读全文
- **公式卡** —— 公式与变量说明绑定。**公式漂在正文里而变量含义散落各处，是技术文档最常见的可用性缺陷**
- **⚠️ 边界提醒** —— 标注结论的适用条件。这是区分"教科书搬运"和"工程可用"的关键：工程上最危险的不是不知道公式，是不知道公式什么时候不成立
- **常见误区** —— 见下

### 附录五件套

理论层整体应配一份附录，包含五项。这五项的共同特点是**高频查询、低频阅读**：

| 项 | 作用 |
|---|---|
| **符号表** | 跨模块符号一致性的唯一裁决处 |
| **公式总表**（按模块归集） | 查公式不用翻正文 |
| **中英术语对照** | 跨语言检索、写英文论文、与外方沟通 |
| **工程数量级速查** | **实际使用频率最高的一页** —— 判断一个数值是否离谱的第一道关 |
| **参考文献** | 溯源 |

「工程数量级速查」尤其值得强调：它是一张"典型值范围表"（如整车质量 1400–2000 kg、附着系数干/湿/雪 0.9/0.6/0.2）。**弱模型最容易犯的错之一是给出量级离谱的数值，有这张表可以自查。** 建议在写数值前强制查表。

### 分层阅读标记

若同一份材料要服务不同读者（管理层 vs 工程师），用标记区分层次，而不是写两份：

- 🟢 概念层：所有人
- 🔵 工程层：需要公式、边界、口径的读者

同源单文件、多层次呈现，避免版本分叉——这也是后面派生 PPT/汇报材料时能保持口径一致的基础。

## 怎么用这份清单

**第一步：勾选。** 对照 M1-M8，逐个判断本项目是否依赖。判断依据不是"这个学科重不重要"，而是"项目资料里有没有出现、评审会不会问到"。

**第二步：定深度。** 每个模块标 深/中/浅：
- **深**：项目的核心创新所在，要能支撑论文和专利论证
- **中**：需要能正确讨论和评估，但不产出原创内容
- **浅**：知道边界和术语即可，主要用于跨部门沟通不说外行话

深度不同，`theory/` 下对应文件的详略差别很大。全都建成"深"是浪费，全都"浅"则评审顶不住。

**第三步：标缺口。** 判断为"该有但当前项目资料覆盖不足"的模块，**同时写进 `theory/MAP.md` 的缺口栏和 `project/OPEN.md`** ——因为这往往不只是知识库的缺口，更是项目本身的短板。M7 功能安全在样机阶段尤其常见。

**第四步：建完回头校准。** 项目层建成后，用卡片里的「涉及的理论主题」字段反查：有没有资料反复提到、但清单里没勾的学科？有就补。
