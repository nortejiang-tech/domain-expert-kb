# domain-expert-kb

把一个技术方向的资料建成**三层知识库**，让 agent 成为该方向的专家助手，并据此产出 PPT、汇报材料、会议提纲、论文和专利交底书。

## 这个 skill 解决什么问题

"读一批文档然后回答问题"和"成为某个技术方向的专家助手"是两件事。后者要多做三件：掌握项目的**活状态**（不只是文档写了什么，还有做到哪一步、当初为什么选这条路）、补全**公开理论**、产出**专业交付物**。

三件事凑在一起会产生一个新的、更危险的失误模式：**来源串味**。把教科书理论当成团队成果去汇报是尴尬；把公开的现有技术当成自己的发明写进专利，是法律风险。

所以这套方法的骨架是三层知识严格分离：

| | 项目层 | 理论层 | 对标层 |
|---|---|---|---|
| 内容 | 你的文档、数据、决策、进度 | 公开的学科理论与工程方法 | 竞品、学术文献、专利现有技术 |
| 权威性 | 对"我们在做什么"唯一权威 | 对"原理是什么"权威 | 对"别人做到哪"权威 |
| 保密性 | **机密** | 公开 | 公开 |
| 变化速度 | 快，需持续同步 | 慢，可长期冻结 | 中等 |

每类交付物就是这三层的不同配比：汇报＝项目层为主+对标层定位；论文＝理论层背景+对标层 related work+项目层贡献；专利＝对标层现有技术+项目层技术方案。分好层之后，写材料从"从零组织"变成"按配方取料"。

## 为弱模型设计

这套方法论有一个明确的设计目标：**让弱模型也能产出接近强模型的质量**。三个关键机制：

1. **认知负担前移** —— 所有需要"聪明"的工作放在建库阶段（离线、可重跑、可以用更强的模型跑一次），查询阶段降级为查表+填模板
2. **素材块** —— 把反复要用的论述（项目定位、技术路线、关键指标、核心难点、差异化优势）预先写好、经人审定、存成文件，每块三种长度。弱模型的任务从"创作"变成"组装"
3. **按保密性与算力需求切分环境** —— 最吃模型能力的理论层和对标层恰好**不含机密内容**，可以在强模型 + 联网环境建好、冻结成 markdown 带回受限内网；项目层留在内网

第 3 点对受限企业网络尤其有用：境外学术站点在内网打不开，所以文献摘要要**全文内嵌**而不是只存链接。

## 安装

**Claude Code / 支持 SKILL.md 的 agent**

```bash
git clone <repo-url> ~/.claude/skills/domain-expert-kb
```

或从 Releases 下载 `.skill` 包安装。

**Cline / Qwen Code 等不支持 SKILL.md 的 agent**

见 `references/porting-to-other-agents.md`，内含可直接粘贴进 `.clinerules` / `QWEN.md` 的精简版，以及针对弱模型的分步驱动技巧。

## 用法

**完整建库**（六步，每步产出文件后停下确认）

```
建库第0步            勘察 + 写专家人设 PROFILE.md
建库第1步 <目录>      逐份资料建卡（本地 + 飞书）
建库第2步            抽取 TIMELINE / DECISIONS / OPEN
建库第3步            理论层（对照学科模块清单 M1-M8）
建库第4步            对标层（文献 + 专利 + 竞品）
建库第5步            素材块，逐块审定
```

**单独做文献/专利检索**（不必建整个库）

```bash
python3 scripts/paper_search.py "主题关键词"       # arXiv + Crossref
python3 scripts/patent_search.py '"主题关键词"'     # Google Patents，中英文均可
```

**生产交付物**

先定规格（读者、场合、篇幅、密级），再按 `references/deliverables.md` 的配方取料。

## 几条不能妥协的纪律

- **三层来源任何时候不得混淆**，读者必须能分辨哪句话属于哪层
- **每条事实性结论必须有可核对的出处**
- 理论层区分 `[已查证]` 与 `[仅模型知识]`，后者写进论文专利前必须补查
- 专利检索脚本**刻意不输出"风险等级"** —— 判断是否构成障碍需逐条比对权利要求，没依据的风险判断比留空危险
- 论文与专利同时进行时，提醒确认**先申请专利再发表** —— 论文公开可能破坏自己专利的新颖性

`references/build-playbook.md` 中贯穿使用的四轮独立转向（4WIS）项目示例——包括决策记录、时间线里的指标数字——**均为虚构的模板示例**，用于说明格式，不代表任何真实项目数据。
